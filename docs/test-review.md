### Review pass

- **`%DATE% %TIME%` parse-time semantics** — verified against `afk_clicker.py:883-892`'s own comment and standard `cmd.exe` behaviour: `%VAR%` (non-delayed) expands at parse time for every line, including inside a `( ... )` block, where the whole block is parsed once before any line in it executes. The one line inside such a block (`done`, gated by `if %RC% LSS 8 ( ... )`) is therefore timestamped a negligible instant before it actually runs, not after — the doc calls this out explicitly rather than treating it as a bug. Correct, and immaterial for a human-read log.
- **`.sh` `$(date '+%Y-%m-%d %H:%M:%S')` inside a double-quoted `echo` string that also interpolates `{staged}`/`{target}`/`{relaunch}`** — no new injection surface: command substitution and variable interpolation already applied to this same double-quoted string before Round 3 (a `staged`/`target`/`relaunch` value containing a backtick or `$(...)` was already executable in the pre-existing `echo "start pid=... staged={staged} ..."` line). Adding a second, hardcoded `$(date ...)` at the front changes nothing about that pre-existing, out-of-scope risk class. Not a new must-fix; worth a one-line note next to the existing `%`-in-`.cmd` caveat in `docs/implementation.md`'s "Known, pre-existing, not expanded" section next time someone is in that area (nit, not blocking).
- **New fixture helpers' cleanup** — `_build_relaunch_exe`'s copied `python.exe` + DLLs live under the same `workdir` that `addCleanup(shutil.rmtree, workdir, ...)` already removes; `_kill_stragglers` covers a stuck `relaunch.exe` via the existing `*afk-repro*` `CommandLine` match (see test case 10 above) and runs before the `rmtree` cleanup fires, so a locked file doesn't block teardown. No leak found.
- **Diagnostics can't fail the suite** — confirmed (test case 11 above); no change needed.
- **Doc accuracy** — `docs/implementation.md`'s Round 3/4 sections were checked claim-by-claim against raw CI logs fetched directly this session (runs 34904637357 and 34906199873), not trusted from the doc: every quoted `update.log` line, every `succeeded=True/False` diagnostic result, and the `Ran 314 tests ...
